# Views architecture and formulas

This document records the checked-in D-073 implementation. The code, not this document, is authoritative for executable defaults. A required request field with no in-code default is identified as caller supplied.

## Projection contract and source boundary

The shared types are in [`contract-types.ts`](../../ui/src/projection/contract-types.ts): `RawSourceLedger`, `SemanticGraphSnapshot`, `AnalyticalDomain`, `ProjectionRequest`, `MathematicalProjection`, `ProjectionResult`, `RecursiveLevel`, `VisualRelation`, `RenderVisibility`, `PickResult`, and style/renderer interfaces. The four IDs are `natural`, `indras-pearls`, `fractal`, `holographic`; dimensions are `2d|3d`. Types are shared declarations; they do not themselves imply that each projection is mounted by the current page.

`normalize.ts` exports `normalizeRawLedger`, `createSemanticSnapshot`, `canonicalRawJson`, `canonicalSourceBytes`, `canonicalLedgerBytes`, `assertRawLedger`, and `assertSemanticSnapshot`. Version strings are `raw-ledger-v1`, `v2-standing-v1`, `v2-source-weight-or-one-v1`, and `v2-page-passage-v1`. The ledger retains complete parsed JSON, source path, ordinal, canonical JSON, and presence distinctions. Its digest is SHA-256 over `raw-ledger-v1\\n` followed by 8-byte unsigned big-endian length-prefixed UTF-8 canonical JSON records in manifest, schema header, node, edge, detail order. Object keys use Unicode codepoint order; arrays retain source order; finite numbers use ECMAScript shortest round-trip spelling, including `-0`. Strict JSON ingestion rejects duplicate keys, nonfinite numbers, cycles, accessors, decorated/sparse arrays, invalid strings, and non-JSON values. `SemanticNode` retains the exact raw node or detail-passage record; passage materialization is explicitly `v2-page-passage-v1`. Standing is derived by `v2-standing-v1`; the exact raw status remains available. Edge `analysisWeight` is source `weight` when present and `1` otherwise (`v2-source-weight-or-one-v1`); it does not modify the source row.

The analytical domain is selected in [`domain.ts`](../../ui/src/projection/domain.ts), exports `selectAnalyticalDomain` and `selectDisclosedAnalyticalDomain`. Its defaults are `v2-visible-disclosed` / version `1`, level policy `v2-visible-pages-v1`, and cap 850. It sorts selected IDs by codepoint, includes exactly source-induced edges, and hashes snapshot digest, named policies, and sorted IDs into `domainDigest`. The full ledger remains addressable; nodes outside the domain get no coordinates or fields. A visual subset is not a new projection domain.

[`contract.ts`](../../ui/src/projection/contract.ts) exports `VISUAL_ID_PREFIX` (`visual:`), `validateProjectionResult`, `validateRenderVisibility`, `validatePickResult`, and `validateSemanticEdgeCarriers`. Its `ProjectionWitnesses` require independent membership and lifted-route witnesses. Validation enforces one dimensional coordinate map, exact coordinate/loaded-ID equality, induced source edges, finite values, unloaded-level stubs without member/edge lists, current load tokens, and empty coordinate/positioned-visual state on refusal. A `VisualRelation` has `semantic:false`; structural co-membership and synthetic containment may have no underlying edge IDs. A lifted route must enumerate its exact source-edge contributors. No visual ID, route, curve, container, or field is a semantic edge or an attestation.

[`invariants.ts`](../../ui/src/projection/invariants.ts) exports `assertProjectionInvariants` and checks the raw byte oracle, snapshot and ledger handle, recomputed domain/cap/induced edges, result witnesses, and semantic edge carriers. It does not claim a fixture was run unless separately recorded.

## Registry, cache, page contract, and worker

[`registry.ts`](../../ui/src/projection/registry.ts) exports `ProjectionRegistry`, `ProjectionResultCache`, `projectionParameterDigest`, `projectionCacheKeyDigest`, and `PROJECTION_CACHE_CAPACITY=128`. The key version is `projection-cache-key-v1`; key components are snapshot/domain digest, algorithm ID/version, declared dimension, canonical typed parameters, and requested level ID (or null). Canonical parameter encoding sorts object keys and rejects unsupported/nonfinite values. The LRU coalesces concurrent identical computations, tracks hits/misses, and evicts oldest completed results above capacity. There is no time-based invalidation.

The typed render contract is in `contract-types.ts`: `RenderVisibility` carries result digest, increasing host revision, density in `[0,1]`, loaded level IDs, and six separate ID sets (nodes, source edges, visual relations, curves, containers, fields). `LodHints` supplies separate caps and priorities. `ProjectionRenderer.mount(styled, visibility)` is the initial host operation; `updateVisibleSubset(styled, visibility)` is the same-host update. `validateRenderVisibility` rejects IDs outside their own collection, visible source edges with hidden endpoints, stale result digests, invalid density, and caps exceeded. `PickResult` discriminates nodes, source semantic edges, visual relations, containers, curves, and fields; the validator requires the picked ID to exist in its matching result collection. These are typed seams and validators; they do not establish that every renderer/page path already uses them.

The four-view product bridge is [`render-common/projection-style.ts`](../../ui/src/render-common/projection-style.ts), with shared label policy in `render-common/labels.ts`. `styleProjection` derives display records from the immutable result and source snapshot: morphology (`stellar|neural|mycelium`), reading (`attested|exploratory|combined`), palette, size/brightness, relation widths/alpha, focus dimming, label candidates and density budgets. Labels use source `display_label` when present (otherwise title), a compact 33-character display form, and the shared candidate/budget rules. Morphology and style are presentation-only; they do not enter projection coordinates or result digests.

Page integration resides in [`v2-page.ts`](../../ui/src/review/v2-page.ts), the typed product bridge, and the review product view. Natural, Indra, Fractal, and experimental Holographic are registered typed views; the worker entry includes all four. The generic six-set visibility API remains a typed contract and validator, so its declarations alone do not prove every renderer path uses in-place subset updates.

The generic host/client/wire code is in [`worker-protocol.ts`](../../ui/src/projection/worker-protocol.ts), [`worker-host.ts`](../../ui/src/projection/worker-host.ts), [`worker-client.ts`](../../ui/src/projection/worker-client.ts), and [`worker-entry.ts`](../../ui/src/projection/worker-entry.ts). Protocol version: `projection-worker-v1`. Commands are `project` and `cancel`; project carries request ID, slot, projection ID, snapshot/domain digests, parameters, optional requested level, and optional attached snapshot. Events are `ready`, `result`, `failure`, `cancelled`. Failure codes: `unknown-projection`, `unknown-snapshot`, `snapshot-digest-mismatch`, `domain-snapshot-mismatch`, `invalid-parameters`, `projection-error`, `protocol-violation`. One task per slot is active; a newer request aborts its predecessor, stale results are suppressed. Host snapshot capacity defaults to 4; result cache defaults to 128. The current `PROJECTION_WORKER_ENTRY_PROJECTIONS` list registers Natural, Fractal, Indra, and Holographic. The worker bundle is embedded in `review.js` and started from a Blob URL; when Worker is unavailable the same host can run on the main thread. Host idle state schedules no timers or animation frames.

## Natural

Implementation: [`natural-bridge.ts`](../../ui/src/projection/natural-bridge.ts), exports `naturalProjection`, arrangement resolvers, dispatch table, and version constants. Algorithm `natural-bridge-v1`; pinned layout `d072-layout-v2`; numeric backend `javascript-number-v1`. It calls existing `computeLayout` and `projectRelations`, then applies volume expansion in 3D. Dispatch is `constellation → flat-stellar`, `network → flat-organic`, `mycelium → flat-organic`; default arrangements when a request is created are respectively the same three values. An explicit arrangement wins and a later morphology change does not recalculate it.

Request parameters are dimension; arrangement; exact layout version; relation policy (`attested-essential`, `exploratory-essential`, `combined-essential`); positive finite `volumeExpansion.{x,y,z}`; optional finite in-domain `continuityAnchors`. The current page maps reading `attested|exploratory|all` to those three policies and passes appearance expansion values; the appearance baseline is `(1,1,1)`. There is no Natural parameter-range default in the projection function. The style defaults are request-creation defaults, not solver parameters. Node IDs must be unique/codepoint-sorted; edge IDs must exactly induce from the source snapshot; domain is at most 850 and fully loaded. Formula/transform: the existing D-072 layout yields positions; in 3D the bridge canonicalizes then applies `(expandX, expandY, expandZ)`; in 2D it preserves layout coordinates. It refuses via thrown validation errors for snapshot/domain mismatch, unsupported version/arrangement/dimension/relation policy, invalid expansion/anchors, unknown IDs, incorrect induced edges, wrong pinned branch, omitted/nonfinite coordinates. It emits `visual:natural:*` relations with contributor source IDs; structural layouts carry `semantic:false`. Known limit: this is a pinned legacy layout bridge, not a new layout solver; `exploratory-essential` and `combined-essential` both use D-072 combined reading, while attested-essential filters to attested.

## Indra's Pearls

Assembly: [`projection/indra.ts`](../../ui/src/projection/indra.ts), `indrasPearlsProjection`. Supporting exports are in [`indra/complex.ts`](../../ui/src/indra/complex.ts), [`mobius.ts`](../../ui/src/indra/mobius.ts), [`schottky.ts`](../../ui/src/indra/schottky.ts), [`assignment.ts`](../../ui/src/indra/assignment.ts), [`levels.ts`](../../ui/src/indra/levels.ts), and [`geometry3d.ts`](../../ui/src/indra/geometry3d.ts). Algorithm `indras-pearls-projection-v1`; numeric backend is the concatenation of `indra-assignment-v1/indra-levels-v2/indra-half-space-v1/indra-fallback-nested-spheres-v1/javascript-number-v1`. Construction policy `ring-packing-v1`; layout `indra-pearl-layout-v1`; importance `v2-importance-value-passage-zero-v1`; explanation `indra-explain-v1`.

Complex helpers provide finite arithmetic and scale-safe division. Möbius maps use `f(z)=(az+b)/(cz+d)`, normalized determinant-one representatives, inverse/round-trip and condition witnesses. Pole detection defaults to relative epsilon `1e-14`. Paired-disc images use the exact circle image formula; strict non-overlap is required. Schottky validation option defaults: separation margin `1e-6`, determinant floor `1e-12`, tolerance `1e-9`, condition bound `1e9`, round-trip tolerance `1e-9`. Construction requires genus ≥2. Ring orientation is digest-based `indra-ring-orientation-v1`; ring packing is `packPairedDiscsOnRing` with deterministic child ordering and tested packing refusal. When there are too few hierarchy children (minimum 4) or Schottky validation/packing cannot certify a group, code selects the explicitly labelled nested-sphere fallback (`indra-fallback-nested-spheres-v1`), not a Schottky claim.

For paired equal-radius discs `A_i=D(a_i,r_i)`, `B_i=D(b_i,r_i)`, the generator is `f_i(z)=b_i+r_i²/(z−a_i)`, with matrix `[[b_i, r_i²−a_i b_i],[1,−a_i]]`; normalize by a deterministic square root of its determinant to determinant one and canonicalize the matrix sign. Reduced words forbid adjacent inverse letters; the depth-`d` count is `2g(2g−1)^(d−1)`. Primary-parent hierarchy partitions members without duplication; the node keeps its source ID and belongs to the exact induced subgraph of its pearl. The upper-half-space extension used for 3D is `Q=|cz+d|²+|c|²t²`, `z'=((az+b)overline(cz+d)+a overline(c)t²)/Q`, `t'=t/Q`, with `t>0`. The checked fallback sphere packing is a navigation metaphor, not a Kleinian limit set.

Projection parameters: dimension; `maxDepth` integer 1–16; positive integer `maxWords` (no upper bound is encoded beyond the cap itself); generator policy must be `ring-packing-v1`; tolerance in `(0,0.05]`; `expandZ` in `[0.3,2.5]`. The call site supplies these values; no parameter defaults are defined by `ProjectionParameters`. The theoretical word count at depth `d` is `2g(2g−1)^(d−1)`. `indra-levels-v2` plans one pearl load lazily: depth 1 opens at most `2g` children; deeper loads open at most `2g−1` reduced-word extensions of that pearl, subject to `maxWords`, depth cap, and the per-pearl `nodeBudget`. The whole-depth count is diagnostic and does not prevent an otherwise in-budget single-pearl load. Lazy level IDs/tokens bind snapshot, domain, parameter hash, projection, levels version, and level; `INDRA_LEVEL_CACHE` is a bounded LRU keyed by that complete token and caches completed loads only. Unopened levels carry count/digest/token only, no member lists or positions; opening loads reduced-word children and their exact member and induced-edge IDs. Layout assigns hierarchy members to deterministic pearl slots, then node positions from importance and the pearl layout; 3D uses the Poincaré upper-half-space extension with `t>0`, with height clamped to declared sphere bound `0.95` and `expandZ` bounds above. Diagnostic witnesses include genus, minimum separation/margin, max matrix condition, determinant/identity deviation, exterior-map ratio, inverse round-trip, word conditions, depth/word counts, member conservation, and cross-pearl edges.

Typed refusal codes include the projection-level `pole-in-disc` refusal for a Möbius pole inside a closed disc, plus `invalid-request`, `invalid-hierarchy`, `stale-load-token`, `level-not-found`, `invalid-genus`, `invalid-depth`, `depth-cap-exceeded`, `word-cap-exceeded`, `unstable-word`, `fallback-packing-failure`, `geometry-containment`, `member-conservation`, and `orbit-failure`; Schottky construction additionally distinguishes `insufficient-genus`, `insufficient-children`, `invalid-child-weight`, `nonfinite-component`, `nonpositive-radius`, `circle-overlap`, `degenerate-determinant`, `determinant-one-error`, `inverse-identity-error`, `condition-bound-exceeded`, `exterior-map-violation`, `inverse-round-trip-failure`, and `packing-failure`. Known limit: the fallback nested spheres are explicitly illustrative, not a limit set; 3D is limited to the valid extension/construction or labelled fallback.

## Fractal

Assembly [`projection/fractal.ts`](../../ui/src/projection/fractal.ts), `fractalProjection`; parameter certification [`fractal/parameters.ts`](../../ui/src/fractal/parameters.ts); forward map [`fractal/botcher.ts`](../../ui/src/fractal/botcher.ts); inverse rays [`fractal/inverse-rays.ts`](../../ui/src/fractal/inverse-rays.ts); assignment [`fractal/assignment.ts`](../../ui/src/fractal/assignment.ts); regions [`fractal/regions.ts`](../../ui/src/fractal/regions.ts); explanation [`fractal/explain.ts`](../../ui/src/fractal/explain.ts). Versions: `fractal-projection-v1`, `fractal-parameters-v1`, `botcher-series-v1`, `inverse-rays-v1`, `sector-locality-v2`, `fractal-assignment-v2`, `bfs-reversal-dfs-spectral-refined-median-v2`, `component-fiedler-order-v1`, `circular-relocate-reverse-v1`, `fractal-regions-v1`, `fractal-explain-v1`; numeric backend records the Böttcher, inverse-ray, assignment, dense and Lanczos versions.

Dynamics are certified before projection. For community count `C`, `p=2+(C mod 2)` (2 or 3); induced attested density `d=0` for `n<2`, else `min(1,2m_a/(n(n−1)))`; `c=0.05(2d−1)` so `|c|≤0.05`. The fixed point solves `z^p+c=z`, must have multiplier `|p z*^(p−1)|<1` and residual ≤`1e-12`. The critical orbit `z_(k+1)=z_k^p+c`, `z_0=0`, is checked for 64 iterations, against escape radius `r^p−r=|c|`, and convergence to `z*` ≤`1e-12`. Potential by importance midrank `q=(rank+1/2)/n` is `G=0.25+1.5q`; thus the node potential range is the exact midrank range. Display scale is `100 sqrt(max(n,1)/172)`. Ray iterations default to the smallest N in 1..24 whose conservative Böttcher-series tail bound at minimum potential is ≤`1e-12` (N=1 when `c=0`).

Forward Böttcher evaluation is the finite product/log series for `Φ_c(z)` with `Φ_c(F_c(z))=Φ_c(z)^p`; inverse mapping solves `Φ_c(z)=w`, `w=exp(G+iθ)`, by branch-continuous Newton continuation. Caller parameters are `dimension`, certified `power`, `rayIterations` (positive integer; implementation accepts any positive value), `[min,max]` potential with `0<min≤max`, positive finite scale, residual tolerance in `(0,1e-6]`, and exact `sector-locality-v2`. Contract helper `fractalContractParameters` supplies the certified power, potential range, default ray iteration count, scale, policy version, and default residual tolerance `1e-6`.

`sector-locality-v2` assigns contiguous community sectors with base `b(C)=min(π/180,π/C)`, remaining angle `R=2π−Cb`, and `w_j=b+R n_j/n`; final endpoint correction tolerance is `1e-12`. Node angles are internal to guarded sectors. For ordinary communities, deterministic BFS, reversed BFS, ID-tied DFS, spectral Fiedler order and its reversal are candidates; choose by median circular length of original attested intra-community edges (ID-sequence tie break), then try bounded circular relocate/reverse refinement and rescore it with the same rule; communities of ≥4 use the 40/20/40 slot pattern. Giant communities (> half of domain) subdivide only by real primary-hierarchy children with ≥2 members; leaf children/direct members fill the residual span ordered by the residual induced-subgraph Fiedler vector. Disconnected or tied (`λ3−λ2≤1e-10`) residual graphs use deterministic importance/ID BFS. Per eligible community and group sub-sector, edge-locality ratio `L/L_random≤0.5` against 16 SHA-256-seeded Fisher–Yates baselines is required. Refusal if sector endpoint correction >`1e-12`, invalid hierarchy partition, inverse residual exceeds requested tolerance, mapped radial IQR/median <`0.15`, or edge-locality gate fails.

Regions sample the true sector boundaries via inverse rays; three equipotential curves (range endpoints and midpoint) use 49 samples. 3D is a labelled scalar lift of the potential `G`, not a 3D dynamical fractal. Numerical/assignment failures include `invalid-request`, `invalid-features`, `uncertified-fixed-point`, `unbounded-critical-orbit`, `invalid-sector-partition`, `edge-locality-refusal`, `inverse-ray-failed`, and `radial-spread-refusal`; inverse-ray helper outcomes further distinguish `invalid-options`, `nonfinite-target`, `target-not-exterior`, `evaluation-failed`, `damping-failed`, `max-iterations-exceeded`, and `branch-discontinuity`. Witnesses include `p,c,d`, iterations, community/node counts, inverse residual and N/N+1 level agreement, branch argument step, region/equipotential residuals, mapped retention, radial quartiles/spread, and per-group locality. The projection-level no-coordinate refusal is `invalid-sector-partition`; other numerical failures are typed projection errors rather than fabricated coordinates.

## Holographic — experimental

Assembly: [`projection/holographic.ts`](../../ui/src/projection/holographic.ts); adjacency, solvers, signals, heat, recovery, geometry and explanations are in `ui/src/holographic/`. Projection version is `holographic-projection-v5`; geometry is `holographic-geometry-v4`; adjacency is `holographic-adjacency-v1`; dense backend is `jacobi-cyclic-v1`; sparse backend is `thick-restart-lanczos-householder-ql-v2`; canonical degenerate-cluster axes are `projector-probe-v2`. It remains experimental graph-signal analysis.

Attested weighted adjacency is `A_ij=Σw_e`; parallel edges sum, directed `w` contributes symmetrically as `w/2`, and self-loops are excluded. `D_ii=Σ_j A_ij`, `L=D−A`; exploratory edges remain a separate channel. Weight policies are `attested-unit-v1` or `attested-explicit-v1`. Per attested connected component, solve the symmetric normalized Laplacian `N=D^(-1/2) L D^(-1/2)` (zero on isolates). The dense Jacobi reference is used through 172 component nodes. Above 172, bounded restarted Lanczos uses full reorthogonalization and a private symmetric Householder reduction/implicit QL projected solve, capped at 512 projected columns; refusals are typed, with no silent dense substitution. A certified simple unit-weight cycle uses exact Fourier modes and the returned modes still pass residual/orthogonality checks. Default target is up to 24 nontrivial modes, up to 8 restarts, residual/orthogonality tolerance `1e-8`; the default restart size is `min(n−c,max(2k+8,256))` and explicit values above 512 refuse.

The normalized orthonormal eigenbasis `U` is computed once per projection and shared by geometry, heat and reconstruction. For heat, `ψ_(t,v)=U exp(−tΛ) Uᵀδ_v`; the feature signal defaults to source `importance.value`, and heat times are caller-supplied, at most 8 nonnegative finite values. Reconstruction fits sampled coefficients by minimizing `||P_S U_k a−x_S||²+λ||a||²`, then estimates `x*=U_k a`; it reports rank/condition, held-out relative error and MAE against the declared global-mean and local-neighbour baselines. Exact recovery is claimed only for a bandlimited signal, full-rank samples and zero ridge. A separate structural reconstruction witness measures (per region and band) sample rank, condition, uniqueness, relative complement errors for displayed embedding and band-limited community indicators, band residuals, and whether either signal reconstructs exactly. These are signal witnesses only: no recovered node, edge, provenance or truth is inferred.

G6 canonical axes use `projector-probe-v2`: eigenvalue clusters within `τ=1e-8 max(1,||N||₂,|λ_i|,|λ_(i+1)|)` are treated as subspaces; deterministic SHA-256 ±`1/√n` probes are projected into a cluster and twice reorthogonalized, then canonicalized with the declared pivot-sign convention. Full cluster multiplicity and neighboring-gap checks remain; the zero cluster is skipped and the requested 2 or 3 axes are selected from genuine eigenvectors. Probe ambiguity, an unisolable cluster, insufficient rank or solver failure yields typed `no-coordinates`, with no fallback layout.

G7 geometry is per connected component. For normalized eigenvector `u`, displayed Koren vector is `v_i=u_i/√D_i`, satisfying `L v=λ D v` (isolates use the defined zero convention). Each component's axes are centered by midrange and divided by its maximum axis extent; coordinates are quantized to `1e-10`. Components are ordered by decreasing size then smallest codepoint ID and packed in deterministic unit-x cells centered at `1.5j`, with 0.5-unit gutters; singleton components occupy cell centers. Missing local axes are zero padded, while a connected component lacking requested rank refuses. The same single component bases feed geometry, heat and reconstruction.

Result and explanation witnesses include `coordinateState` (`coordinates` or typed `no-coordinates` with refusal code and explanation ID), per-component solver/backend, residual and orthogonality values, spectral clusters and projector stability, heat/Parseval defects, reconstruction rank/condition and held-out error, plus the structural uniqueness and signal reconstruction fields above. After spectral computation, `coincident-node-ring-v1` applies a deterministic visual offset to coincident or nearby nodes within `1e-8` of the component extent. Nodes in each group, ordered by ID, are placed on a circle with radius 10% of the distance to the nearest distinct point; when all nodes of a component coincide and no distinct point exists, the radius is 10% of the component extent. In 3D the circle lies in the plane orthogonal to the first viewing axis. The offset is for display only: exact spectral coordinates remain in diagnostics and the node explanation. It does not change the basis or exact coordinates, and does not guarantee separation of nodes in different groups.

Known limits: regions and signals are derived analysis, not a claim that a local region contains all graph facts. The structural witness is scoped to its declared regions/signals/bands and measured errors; refusal is not imputed as an estimate.

## Design decisions G1–G8

- **G1:** Natural keeps the tuned legacy layout and hashes the explicit `arrangement`; morphology supplies only its default.
- **G2:** Fractal uses graph importance as potential and coherent community external-angle sectors through certified inverse Böttcher rays.
- **G3:** Projections use an explicit digest-addressed disclosed domain capped at 850; undisclosed nodes receive no coordinates.
- **G4:** Co-membership and containment are typed `semantic:false` visual relations, never source edges or attestations.
- **G5:** Fractal locality is measured against deterministic shuffled baselines, with typed giant-community group sectors and a residual leaf order.
- **G6:** Degenerate Holographic eigenspaces use canonical `projector-probe-v2` genuine eigenvectors or typed refusal.
- **G7:** Holographic uses per-component Koren degree-normalized coordinates and one shared spectral basis for geometry, heat and reconstruction.
- **G8:** After spectral computation, `coincident-node-ring-v1` applies a deterministic visual offset to coincident or nearby nodes within `1e-8` of the component extent. Each ID-ordered group is placed on a circle with radius 10% of the distance to the nearest distinct point; when every node in a component coincides, so no distinct point exists, the radius is 10% of the component extent. In 3D the circle lies in the plane orthogonal to the first viewing axis. The offset is display-only; exact spectral coordinates remain in diagnostics and node explanations. It does not change the basis or exact coordinates, and does not guarantee separation across groups.
